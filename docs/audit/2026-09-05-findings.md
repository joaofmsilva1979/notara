## CRITICAL (block Sprint 1 commit)

### C-1 — SSRF + file:// access via yt-dlp extractors

**File:** `api/worker.py:72-78`
**Category:** Server-Side Request Forgery

yt-dlp supports hundreds of extractors beyond YouTube. Even with the YT_PATTERN regex check, a bypass (see C-2) lets an attacker pass any URL including `file:///etc/passwd`, `http://169.254.169.254` (AWS metadata), or other internal services. yt-dlp will happily follow redirects and fetch internal endpoints.

**Fix in Sprint 1:**
1. Add `--use-extractors youtube` to limit yt-dlp to YouTube extractor only
2. Add `--no-playlist` to prevent playlist-based abuse
3. Replace regex with strict domain check (see C-2 fix)

```python
subprocess.run(
    [sys.executable, "-m", "yt_dlp",
     "--extractor-args", "youtube:player_client=android",
     "--use-extractors", "youtube",
     "--no-playlist",
     "-x", "--audio-format", "mp3",
     "-o", str(audio_path), params["youtube_url"]],
    check=False, stderr=subprocess.PIPE, text=True,
)
```

### C-2 — YouTube URL regex bypassable (no end anchor + subdomain/redirect bypass)

**File:** `api/routes.py:27-29`
**Category:** Input Validation

```python
YT_PATTERN = re.compile(
    r'^https?://(www\.)?(youtube\.com/watch\?.*v=[\w-]+|youtu\.be/[\w-]+)'
)
```

No `$` end anchor. Combined with yt-dlp's redirect-following behavior, this can be abused to pass attacker-controlled URLs that satisfy the regex prefix but redirect to internal services.

**Fix in Sprint 1:** Replace regex with strict `urllib.parse` domain check:

```python
from urllib.parse import urlparse

_ALLOWED_YT_HOSTS = {"youtube.com", "www.youtube.com", "youtu.be", "www.youtu.be"}

def _is_valid_youtube_url(url: str) -> bool:
    try:
        p = urlparse(url)
    except Exception:
        return False
    return (
        p.scheme in ("https", "http")
        and p.netloc in _ALLOWED_YT_HOSTS
        and bool(p.path or p.query)
    )
```

Then in `routes.py:70-71`:
```python
if youtube_url and not _is_valid_youtube_url(youtube_url):
    raise HTTPException(status_code=400, detail="Invalid YouTube URL.")
```

## MAJOR (fix in Sprint 1)

### M-1 — torch.load deserialization without integrity check

**Files:** `pipeline/chord_detection_btc.py:100` · `pipeline/transcription_synthtab.py:52`

`torch.load(..., weights_only=False)` uses Python's serialization format. A tampered model file (supply chain, compromised repo clone) executes arbitrary code on deserialization. Attack requires write access to model files on disk — not user-exploitable today.

**Fix:** Add SHA-256 integrity check before loading. Store expected hash in `pipeline/btc/MODEL_HASH.txt` and `pipeline/synthtab/MODEL_HASH.txt`. Verify at startup and raise on mismatch.

### M-3 — Orphaned temp dirs on server restart

**File:** `api/jobs.py` / `api/main.py:19-23`

Cleanup only runs at startup. On Railway/Render with persistent volumes, accumulated temp dirs can fill disk.

**Fix:** Add a periodic `asyncio` task in lifespan that calls `cleanup_expired()` every 30 minutes.
